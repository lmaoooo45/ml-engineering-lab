# Отчёт

## Цель работы

В работе используются готовые модели для четырёх задач: анализ тональности, распознавание речи, классификация изображений и поиск объектов на видео. Модели не обучаются заново. Для текста и аудио используется PyTorch, для изображений и видео используется TensorFlow.

Каждое решение запускается отдельной командой. Для текста есть функция `analyze(text)`, которую позже можно вызвать из API.

## 1. Анализ тональности

**Библиотека и модель.** Используется Hugging Face Transformers и `cointegrated/rubert-tiny-sentiment-balanced`. Библиотека загружает модель и токенизатор через `pipeline`. Токенизатор разбивает текст на части и переводит их в числовые коды.

**Как работает модель.** RuBERT относится к семейству BERT. Механизм внимания помогает учитывать контекст слов. Классификатор выбирает один из трёх классов: положительный, нейтральный или отрицательный. Эта модель выбрана из-за поддержки русского языка и небольшого размера.

**Данные.** По карточке модели, для обучения использованы русскоязычные наборы, собранные Smetanin. Тексты приведены к трём классам, количество примеров сбалансировано по источникам и классам. Структура данных: текст и метка тональности. В `examples/reviews.csv` находятся 12 вручную составленных проверочных примеров, по четыре на класс. Они не использовались для обучения модели.

**Метрики.** Accuracy показывает долю правильных ответов. F1 учитывает ложные срабатывания и пропущенные примеры класса. Macro-F1 получается усреднением F1 по трём классам. Матрица ошибок показывает, какие классы модель путает.

**Реализация и ограничения.** Пустые отзывы и строки длиннее 4000 символов отклоняются. Если текст превышает ограничение модели по токенам, он обрезается. Для оценки `score` используется sigmoid, как в примере автора модели. Оценки трёх классов не обязательно дают единицу в сумме. Модель может ошибаться на иронии и отзывах со смешанной оценкой. После первой загрузки она остаётся в памяти процесса.

## 2. Распознавание речи

**Библиотека и модель.** Используется Transformers и многоязычная модель `openai/whisper-tiny`. Tiny выбрана как небольшая версия, которую можно запускать на обычном процессоре. У крупных версий Whisper распознавание обычно точнее, но требует больше ресурсов.

**Как работает модель.** Сначала звук переводится в мел-спектрограмму, то есть представление изменения частот во времени. Энкодер обрабатывает её, а декодер последовательно формирует текст. В настройках задан русский язык и распознавание речи без перевода.

**Данные.** Whisper обучалась на парах «аудиозапись, текст» с информацией о языке и задаче. В статье о семействе Whisper описан набор из 680 тысяч часов записей. Это данные обучения, а не объём проверки в этой работе. Для собственной проверки нужны аудиофайл и вручную записанный правильный текст.

**Метрики.** WER = (S + D + I) / N. Здесь S обозначает замены слов, D обозначает удаления, I обозначает вставки, N обозначает число слов в эталоне. Ещё можно измерить отношение времени обработки к длительности записи. Если оно меньше единицы, обработка быстрее воспроизведения записи.

**Реализация и ограничения.** Программа принимает WAV, FLAC и OGG до 30 секунд. Каналы усредняются до моно, частота дискретизации приводится к 16 кГц. На шуме или тишине Whisper иногда выдаёт текст, которого не было в записи. Результат нужно сравнивать с эталоном.

## 3. Классификация изображений

**Библиотека и модель.** Используется MobileNetV2 из Keras Applications с весами ImageNet. В библиотеке уже есть модель, обработка входного изображения и расшифровка классов. MobileNetV2 выбрана из-за сравнительно небольшого числа вычислений.

**Как работает модель.** Свёрточная сеть выделяет признаки изображения и оценивает 1000 классов. В MobileNetV2 используются разделяемые по глубине свёртки: пространственная обработка выполняется отдельно для каналов, затем их признаки объединяются. Остаточные связи передают информацию между блоками. Эти приёмы позволяют уменьшить объём вычислений.

**Данные.** Для используемых весов взята классификация ImageNet ILSVRC с 1000 категориями. Каждому изображению соответствует класс. Классы связаны с synset, группами близких по значению слов в WordNet. При собственной проверке фотографии должны относиться к этим категориям.

**Метрики.** Top-1 accuracy показывает, как часто правильный класс стоит первым. Top-5 accuracy показывает, как часто он входит в первые пять ответов. Также измеряется время обработки одного изображения.

**Реализация и ограничения.** Фото переводится в RGB, его ориентация исправляется по EXIF, размер меняется на 224 × 224. Затем вызывается `preprocess_input`, который подготавливает значения пикселей для модели. По умолчанию возвращаются пять классов. Растяжение изображения до квадрата может исказить предмет. Модель оценивает изображение целиком и не выделяет рамки объектов. При каждом запуске команды модель загружается заново.

## 4. Поиск объектов на видео

**Библиотека и модель.** Используется SSD MobileNetV2 FPNLite 320 из TensorFlow Hub. Видео читает и сохраняет OpenCV. Модель выбрана для обработки отдельных кадров без обучения собственного детектора.

**Как работает модель.** SSD за один проход оценивает классы и координаты объектов. MobileNetV2 выделяет признаки, а FPNLite объединяет признаки разных масштабов. Модель работает с размером 320 × 320. Видео обрабатывается как последовательность изображений.

**Данные.** Модель обучена на COCO. Аннотации этого набора содержат ID изображения, класс объекта и рамку. В исходных данных COCO рамка записана как `[x, y, width, height]`. В ответе модели используется `[ymin, xmin, ymax, xmax]`, значения от 0 до 1. Номера классов COCO имеют пропуски, поэтому для названий нужно использовать таблицу соответствий.

**Метрики.** IoU показывает отношение площади пересечения двух рамок к площади их объединения. Для проверки можно считать совпадением рамки одного класса с IoU не меньше 0.5. Precision показывает долю верных находок среди всех находок, recall показывает долю найденных объектов среди всех размеченных объектов. Для большой размеченной выборки используют mAP, среднее качество детекции по классам. Скорость оценивается числом обработанных кадров в секунду.

**Реализация и ограничения.** По умолчанию обрабатывается каждый пятый кадр, результаты с оценкой ниже 0.5 отбрасываются. Координаты переводятся в пиксели и рисуются на кадре. Пропущенные кадры сохраняются без рамок. Это ускоряет работу, но короткое появление объекта можно пропустить. Программа не отслеживает один объект между кадрами и не сохраняет звук. Для длинных роликов потребуется сохранять результаты частями, поскольку сейчас JSON накапливается в памяти.

## Результаты проверки

Прошли 9 тестов обработки данных и метрик. Изображения и видео обработаны готовыми моделями, JSON с ответами сохранён. На фотографии собаки MobileNetV2 выдала класс Samoyed. Видеодетектор на кадрах с той же фотографией ошибочно выбрал кошку.

Текст и аудио пока не проверены с весами моделей: загрузка с CDN Hugging Face вернула HTTP 403. Accuracy, macro-F1 и WER не измерены. Подробности находятся в [validation.md](validation.md), план измерений находится в [evaluation.md](evaluation.md).
